# Set custom DFTB+ parameters

## Use the dictionary form

Every top-level HSD block is a key; nesting mirrors the file:

```python
parameters = {
    "Geometry": {"GenFormat": {"_raw": geometry_text}},
    "Hamiltonian": {"DFTB": {"SCC": True, "MaxSCCIterations": 100}},
    "Analysis": {"CalculateForces": True},
    "Options": {},
}
```

The full translation table is in
[HSD serialisation rules](../reference/hsd-serialisation.md). The four that
cover most inputs:

| You write | You get |
| --- | --- |
| `{"SCC": True}` | `SCC = Yes` |
| `{"Driver": {"ConjugateGradient": {...}}}` | `Driver = ConjugateGradient { ... }` |
| `{"Options": {}}` | `Options {}` |
| `{"KPoints": [4, 4, 4]}` | `KPoints = 4 4 4` |

## Pass anything else through verbatim

Any key starting with `_raw` is written to the file as-is, and the key itself
disappears. Use it for blocks the dictionary form does not model:

```python
"Hamiltonian": {"DFTB": {
    "SCC": True,
    "_raw_1": 'SlaterKosterFiles = Type2FileNames {\n  Prefix = "/opt/skf/"\n  Separator = "-"\n  Suffix = ".skf"\n}',
    "_raw_2": 'MaxAngularMomentum {\n  H = "s"\n  O = "p"\n}',
    "_raw_3": "Filling = Fermi {\n  Temperature [K] = 300\n}",
}}
```

Number the keys (`_raw_1`, `_raw_2`, ...) — they must be distinct, and Python
dictionaries preserve insertion order, so that is also the order in the file.

A dictionary whose *only* key is `_raw` behaves differently: it fills the block
body, which is how geometry gets in:

```python
"Geometry": {"GenFormat": {"_raw": "2  C\n  H\n  1 1 0.0 0.0 0.0\n  2 1 0.0 0.0 0.75"}}
```

## Keep metadata out of the file

Keys starting with a single `_` (but not `_raw`) are skipped entirely. Use them
for anything you want stored and queryable but never written to DFTB+:

```python
"_provenance": {"source": "materials-project", "mp_id": "mp-149"},
```

## Validate before submitting

Wrap the dictionary in a `DftbParameters` node and the top-level block names are
checked immediately:

```python
from aiida.plugins import DataFactory

DftbParameters = DataFactory("dftbplus")
parameters = DftbParameters({"Hamiltoniann": {}})
# voluptuous.error.MultipleInvalid: 'Hamiltoniann' is not a known top-level
# DFTB+ block. Allowed: Analysis, Driver, ElectronDynamics, ExcitedState,
# Geometry, Hamiltonian, Options, Parallel, ParserOptions, Reks, Transport.
```

Only the top level is checked. A typo *inside* a block is DFTB+'s to catch, at
run time, with exit code 310.

## See the file before you submit

```python
print(parameters.get_hsd())
```

```shell
verdi data dftbplus hsd <PK>
verdi data dftbplus hsd <PK> -o dftb_in.hsd
```

This is exactly what would be written, minus the two optional patches (the SKF
prefix rewrite and the output-prefix fix). After a calculation, compare with
what DFTB+ actually understood:

```shell
verdi calcjob inputcat <PK> dftb_in.hsd     # what the plugin wrote
verdi calcjob outputcat <PK> dftb_pin.hsd   # what DFTB+ made of it, defaults included
```

## Use a ready-made file instead

If you already have a `dftb_in.hsd` — generated by another tool, or hand-tuned —
hand it over whole:

```python
from aiida.plugins import DataFactory

inputs["dftb_input"] = DataFactory("core.singlefile")(file="/path/to/dftb_in.hsd")
```

It is copied verbatim; only the two patches may touch it. Exactly one of
`parameters` and `dftb_input` may be given — supplying both, or neither, is
rejected before submission.

The trade-off: a `SinglefileData` is an opaque blob. You lose the ability to
query on settings, which is the main reason to use this plugin at all. Prefer
`parameters` unless you have a specific reason not to.

## Change one setting across many calculations

Never mutate a stored node — AiiDA nodes are immutable, and a copy made outside
a `calcfunction` loses the provenance link. Derive it properly:

```python
from aiida import orm
from aiida.engine import calcfunction

@calcfunction
def with_tighter_scc(parameters, tolerance):
    updated = parameters.get_dict()
    updated["Hamiltonian"]["DFTB"]["SCCTolerance"] = tolerance.value
    return orm.Dict(updated)

tighter = with_tighter_scc(original, orm.Float(1e-7))
```

The graph now records that `tighter` was *derived from* `original`, by this
function, with this argument.
